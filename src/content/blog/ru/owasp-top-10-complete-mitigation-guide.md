## 1. За рамками формального чек-листа: Безопасность как архитектурный фундамент

**OWASP Top 10:2025** — это общепризнанный международный стандарт классификации наиболее критических рисков безопасности современных веб-систем, API и cloud-native архитектур. Однако серьезная ошибка многих инженерных команд — восприятие OWASP Top 10 как исчерпывающего чек-листа соответствия.

Успешное прохождение автоматического сканера не гарантирует безопасность продукта. OWASP Top 10 — это классификатор архитектурных сбоев. Надежная защита требует реализации концепции **эшелонированной обороны (Defense-in-Depth)**, безопасного жизненного цикла разработки (Secure SDLC) и непрерывного моделирования угроз (Threat Modeling).

```
+--------------------------------------------------------------------------+
|                  Многоуровневая эшелонированная оборона                  |
+------------------------------------+-------------------------------------+
                                     |
    Уровень 1: Сеть и периметр       v
    [ WAF / Защита от DDoS / TLS 1.3 / Ограничение скорости запросов ]
                                     |
    Уровень 2: Транспорт и шлюз      v
    [ API Gateway / Валидация OAuth 2.0 & OIDC / Взаимный TLS (mTLS) ]
                                     |
    Уровень 3: Приложение и логика   v
    [ Строгая валидация ввода / Параметризованные SQL-запросы / RBAC & ABAC ]
                                     |
    Уровень 4: Данные и хранилище    v
    [ Шифрование полей / Минимальные привилегии БД / Управление ключами Vault ]
```

## 2. Официальные категории OWASP Top 10:2025 и инженерные меры защиты

### A01:2025 – Нарушение контроля доступа (Broken Access Control)
Сохраняет позицию #1. В редакции 2025 года подделка запросов на стороне сервера (SSRF) официально включена в эту категорию как механизм обхода контроля доступа к внутренним сетям и метаданным инстансов (IMDS).
* **Защита**: Принудительная привязка идентификатора пользователя и тенанта в каждом запросе к базе данных.

### A02:2025 – Ошибки конфигурации безопасности (Security Misconfiguration)
Поднялась на #2 место. Сложность мультиоблачных сред и микросервисов делает дефолтные пароли, открытые порты и утечки стектрейсов критическим риском.
* **Защита**: Автоматизация через IaC, отключение отладочной информации в production, строгие заголовки CSP и HSTS.

### A03:2025 – Сбои в цепочке поставок программного обеспечения (Software Supply Chain Failures)
Новая ключевая категория 2025 года. Расширяет прежнюю категорию устаревших компонентов, охватывая риски внедрения вредоносных пакетов, компрометацию CI/CD конвейеров, подмену зависимостей и отсутствие SBOM.
* **Защита**: Криптографическая фиксация lock-файлов, SCA-сканирование в CI/CD (Trivy, Snyk), жесткая привязка экшенов к коммитам SHA, подпись контейнеров через Cosign.

### A04:2025 – Криптографические ошибки (Cryptographic Failures)
Компрометация конфиденциальных данных из-за устаревших алгоритмов или открытой передачи.
* **Защита**: Хеширование паролей с помощью Argon2id или bcrypt; обязательный протокол TLS 1.3 с заголовком HSTS; шифрование данных алгоритмами AES-256-GCM.

### A05:2025 – Инъекции (Injection)
Внедрение недоверенных пользовательских данных напрямую в интерпретаторы (SQL, командный шелл).
* **Защита**: Исключительно параметризованные запросы (Prepared Statements), строгий запрет конкатенации строк.

### A06:2025 – Небезопасный дизайн (Insecure Design)
Концептуальные архитектурные просчеты на этапе проектирования системы.
* **Защита**: Моделирование угроз по методологии STRIDE, реализация безопасных настроек по умолчанию (Secure Defaults).

### A07:2025 – Ошибки аутентификации (Authentication Failures)
Уязвимость к подбору паролей (brute-force) и угону пользовательских сессий.
* **Защита**: Многофакторная аутентификация (MFA: TOTP/FIDO2), токены с высокой энтропией, хранение сессий в `HttpOnly; Secure; SameSite=Strict` cookies.

### A08:2025 – Сбои целостности программного обеспечения или данных (Software or Data Integrity Failures)
Небезопасная десериализация бинарных объектов, выполнение неподписанных внешних скриптов в CI/CD.
* **Защита**: Запрет опасной десериализации, фиксация полных Git Commit SHA в CI-экшенах, подпись контейнеров через Cosign.

### A09:2025 – Сбои в ведении журналов и оповещении безопасности (Security Logging and Alerting Failures)
Подчеркивает необходимость оперативного оповещения в реальном времени, а не просто пассивного сбора логов.
* **Защита**: Структурированные логи аудита в JSON, централизованная отправка в защищенный SIEM, автоматические алерты на аномальную активность.

### A10:2025 – Некорректная обработка исключительных ситуаций (Mishandling of Exceptional Conditions)
Новая категория 2025 года. Направлена на устранение состояний открытого отказа (Fail-Open), состояний гонки (Race Conditions) и исчерпания ресурсов при сбоях.
* **Защита**: Реализация архитектуры закрытого отказа (Fail-Closed), принудительная блокировка строк БД (`SELECT FOR UPDATE`) при критических операциях.

```typescript
// Пример: Middleware авторизации по принципу Fail-Closed
export async function enforcePolicyMiddleware(req: Request, res: Response, next: NextFunction) {
  let isAuthorized = false; // По умолчанию доступ закрыт (Fail-Closed)
  try {
    const user = extractAuthenticatedUser(req);
    isAuthorized = await policyEngine.evaluate(user, req.path, req.method);
  } catch (error) {
    logger.error('Критический сбой проверки политики доступа', { error });
    isAuthorized = false; // При ошибке доступ гарантированно блокируется
  }
  if (!isAuthorized) {
    return res.status(403).json({ error: 'Доступ запрещен' });
  }
  next();
}
```

## 3. Историческое сравнение: OWASP Top 10 2021 и 2025

| Категория 2021 | Категория 2025 | Основные структурные изменения |
| :--- | :--- | :--- |
| **A01:2021 – Broken Access Control** | **A01:2025 – Broken Access Control** | Сохраняет #1 место. Включает SSRF как вектор обхода контроля доступа. |
| **A05:2021 – Security Misconfiguration** | **A02:2025 – Security Misconfiguration** | Поднялась на #2 место из-за распространения мультиоблачных сред. |
| **A06:2021 – Vulnerable Components** | **A03:2025 – Software Supply Chain Failures** | Переработана и расширена: защита сборки, зависимостей и контроль SBOM. |
| **A02:2021 – Cryptographic Failures** | **A04:2025 – Cryptographic Failures** | Занимает #4 место. Защита данных и современные криптографические стандарты. |
| **A03:2021 – Injection** | **A05:2025 – Injection** | Занимает #5 место. Параметризованные запросы и валидация схем. |
| **A04:2021 – Insecure Design** | **A06:2025 – Insecure Design** | Занимает #6 место. Акцент на моделировании угроз STRIDE. |
| **A07:2021 – Identification & Auth** | **A07:2025 – Authentication Failures** | Упрощено название. Обязательное внедрение MFA и стандарта PKCE. |
| **A08:2021 – Software & Data Integrity** | **A08:2025 – Software or Data Integrity Failures** | Уточнено название. Подпись артефактов и контроль целостности. |
| **A09:2021 – Logging & Monitoring** | **A09:2025 – Security Logging and Alerting Failures** | Акцент смещен на превентивное оперативное оповещение (Alerting). |
| **A10:2021 – SSRF** | **A10:2025 – Mishandling of Exceptional Conditions** | Новая категория. Защита от состояний Fail-Open и гонок. SSRF перенесен в A01. |
